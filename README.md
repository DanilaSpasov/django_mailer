# Django Mailer

**django_mailer** — Django-приложение для создания и ручного запуска email-рассылок. Пользователи могут управлять получателями, сообщениями и рассылками, отслеживать результаты отправки и просматривать статистику.

В проекте реализованы регистрация с подтверждением email, восстановление пароля, роли пользователей, PostgreSQL и кэширование через Redis.

---

# Технологии и стек

* **Язык программирования:** Python 3.14
* **Фреймворк:** Django 6.1
* **СУБД:** PostgreSQL
* **Кэширование:** Redis
* **ORM:** Django ORM
* **Шаблоны:** Django Templates + Bootstrap 5
* **Отправка писем:** Django Email Backend, SMTP Яндекса
* **Менеджер зависимостей:** Poetry
* **Контроль версий:** Git / GitHub

---

# Структура проекта

Проект состоит из двух приложений:

* **mailing** — получатели, сообщения, рассылки и история попыток отправки;
* **users** — регистрация, аутентификация, подтверждение email и управление пользователями.

Общие настройки проекта находятся в каталоге `config`.

# Функциональность

## Получатели

Реализован полный CRUD получателей. Для каждого получателя сохраняются email, Ф. И. О. и комментарий. Пользователь работает только со своими получателями.

## Сообщения

Пользователь может создавать, просматривать, редактировать и удалять собственные сообщения. Сообщение содержит тему и текст письма.

## Рассылки

Рассылка включает:

* дату и время начала;
* дату и время окончания;
* сообщение;
* список получателей;
* статус;
* признак активности;
* владельца.

Статус принимает значения `Создана`, `Запущена` или `Завершена` и пересчитывается в зависимости от текущего времени.

## Отправка писем

Рассылка запускается вручную через интерфейс. Отправка разрешена только владельцу, в установленный период и для активной рассылки.

Письмо отправляется отдельно каждому получателю. Результаты сохраняются одним batch-запросом через `bulk_create()`.

Для каждой попытки сохраняются:

* дата и время;
* результат отправки;
* ответ почтового сервера;
* связанная рассылка.

## Статистика

На главной странице отображаются:

* общее количество рассылок пользователя;
* количество активных рассылок;
* количество получателей;
* успешные и неуспешные попытки;
* количество отправленных писем.

# Пользователи и аутентификация

Используется собственная модель пользователя на основе `AbstractUser`. Вход выполняется по email, поле `username` отключено.

Реализовано:

* регистрация;
* подтверждение email по ссылке;
* вход и выход;
* восстановление пароля;
* блокировка пользователей;
* защита заблокированного аккаунта от повторной активации.

---

# Роли и права доступа

## Пользователь

Пользователь может:

* управлять своими получателями;
* управлять своими сообщениями;
* управлять своими рассылками;
* запускать собственные активные рассылки;
* просматривать собственную статистику.

## Менеджер

Менеджер может:

* просматривать все рассылки и всех получателей;
* просматривать список пользователей;
* блокировать и разблокировать пользователей;
* отключать рассылки.

Менеджер не может редактировать, удалять или запускать чужие рассылки.

---

# Валидация

Для рассылок проверяется:

* дата начала не находится в прошлом;
* дата окончания позже даты начала;
* ручной запуск выполняется в разрешённый период;
* отключённая рассылка не отправляется.

Проверки доступа выполняются на сервере и дополнительно учитываются в шаблонах.

---

# Кэширование

Статистика главной страницы кэшируется в Redis отдельно для каждого пользователя на 60 секунд.

Клиентское кэширование настроено через приватный HTTP-заголовок `Cache-Control`. Персональная страница может храниться только в браузере текущего пользователя.

# Переменные окружения

Создайте файл `.env` на основе `.env_example`:

```
cp .env_example .env
```

В `.env` указываются:

* `SECRET_KEY`;
* параметры подключения к PostgreSQL;
* `REDIS_URL`;
* настройки SMTP и данные почтового аккаунта.

Файл `.env` содержит секретные данные и не должен добавляться в Git.

# Установка и запуск

Для проекта требуются Python 3.14, Poetry, PostgreSQL и Redis.

1. Клонируйте репозиторий и перейдите в каталог проекта:

```
git clone https://github.com/DanilaSpasov/django_mailer.git
cd django_mailer
```

2. Установите зависимости:

```
poetry install
```

3. Создайте базу данных PostgreSQL и заполните `.env`.

4. Запустите Redis и проверьте соединение:

```
brew services start redis
redis-cli ping
```

Ожидаемый ответ — `PONG`.

5. Примените миграции:

```
poetry run python manage.py migrate
```

6. При необходимости создайте суперпользователя:

```
poetry run python manage.py createsuperuser
```

7. Запустите сервер:

```
poetry run python manage.py runserver
```

# Настройка менеджеров

Группа `Менеджеры` создаётся через административную панель. Для неё необходимо выбрать права:

* просмотр всех получателей;
* просмотр всех рассылок;
* отключение рассылок;
* просмотр пользователей;
* блокировка пользователей.

После сохранения группы нужный пользователь добавляется в неё через раздел `Users`.

# Основные страницы

* `/` — главная страница и статистика;
* `/recipients/` — получатели;
* `/messages/` — сообщения;
* `/mailings/` — рассылки;
* `/users/register/` — регистрация;
* `/users/login/` — вход;
* `/users/password-reset/` — восстановление пароля;
* `/admin/` — административная панель.
